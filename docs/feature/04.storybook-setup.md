# 04. Storybook Setup

## Goal
- Introduce Storybook for the frontend, as planned in `docs/training-material-plan.md` (§2.1/§2.3: atoms/molecules-only catalog, same as Takazono.Olive).

## Scope
- `src/Takazono.Ojt.Web` only: Storybook config + a first set of example stories for existing molecules.

## Non-Scope
- Stories for `pages`/`organisms`/`templates` layers (out of scope per the plan; those depend on API/Redux state and are exercised via the real app instead).
- Chromatic/visual-regression or CI integration for Storybook (left for a later step, alongside the CI work in `docs/training-material-plan.md` §2.7).

## Implemented
- Ran `storybook init` (type `react`, builder `vite`, features `docs`+`a11y`) against the existing Vite+React+TS+MUI project; kept the current best-practice defaults (Storybook 10, no `@storybook/addon-essentials` — its features are core in v9+) instead of copying Olive's older Storybook 8 setup.
- Removed the generated example scaffold (`src/stories/*`, demo Button/Header/Page components and assets) — not relevant to this project's design system.
- Rewrote `.storybook/preview.tsx` to mirror `src/App.tsx`'s real provider stack (Redux `Provider` + `PersistGate` + MUI `ThemeProvider`/`CssBaseline` + `SnackbarProvider`), swapping the real `AppRouter` for a `MemoryRouter` so router-dependent molecules (e.g. `Breadcrumbs`) render correctly. The `@/` path alias resolves automatically because `@storybook/react-vite` merges the project's own `vite.config.ts`.
- Added `.storybook/main.ts` and `.storybook/preview.tsx` to `tsconfig.node.json`/`tsconfig.app.json` respectively, so `tsc -b` type-checks the Storybook config too (previously only `src` and `vite.config.ts` were covered).
- Added a first batch of co-located stories (`Component.stories.tsx` next to `Component.tsx`, matching Olive's co-location convention but without introducing Olive's one-folder-per-component structure, since Ojt's atoms/molecules are already flat files):
  - `components/molecules/Common/Breadcrumbs.stories.tsx`
  - `components/molecules/Common/Pagination.stories.tsx` (interactive, holds local state to demo page/size changes)
  - `components/molecules/Common/SortableTableHeaderCell.stories.tsx` (wrapped in a real `<Table>` context)
  - `components/molecules/Common/ConfirmDialog.stories.tsx`
  - `components/molecules/ReactHookForm/ReactHookFormSwitch.stories.tsx` (wrapped in a demo component providing `useForm()`'s `control`, since the real prop requires a live RHF context)
- `components/atoms/Mui` was intentionally left without stories: it is currently a plain re-export barrel of raw MUI components (no project-specific wrapper logic yet), so there is nothing distinct to catalog yet.

## Validation
- `tsc -b`: no errors (stories + `.storybook` config now type-checked)
- `npm run build`: success, bundle size unchanged (story files are not reachable from `src/main.tsx`, so they don't leak into the app bundle)
- `oxlint`: ok (had to name the inline `render:` functions, e.g. `function PaginationDemo(args) {...}`, instead of anonymous arrows — the `react-hooks/rules-of-hooks` rule doesn't recognize hooks called inside an anonymous function assigned to an object property as a component)
- `npm run build-storybook`: success, all 5 stories built into `storybook-static/` (removed afterwards, it's a disposable build artifact and already gitignored)
- Not run: `npm run storybook` (interactive dev server) — recommend a quick visual check before merging, especially the `Pagination`/`SortableTableHeaderCell` interactive stories.
