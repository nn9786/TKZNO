# 前提・方針

## 目的

React／Typescript未経験者（JavaScriptの基礎知識は保有）が、実際に画面実装を行いながら React／Typescript の開発手法を学べる教材を作成したい。

学習者は、用意された手本実装を参考にしながら、類似画面や類似機能を自ら実装していく形式を想定しています。


## 教材の対象範囲

主な対象は、以下に近いレベルのマスタ管理画面です。

```text
src/Takazono.Olive.Web/src/components/pages/Master
```

一覧検索・新規作成・編集・削除などの基本的な CRUD 操作を中心とします。

業務系画面については難易度が高いため、初期スコープには含めず、将来的な追加を想定します。

---

## 実装方針

### 手本実装

手本となる実装は AI コーディングで作成し、非初学者がレビューします。

学習者は、その手本を参考にしながら、同等レベルの別機能を実装する形式とします。

### フロントエンド基盤

既存プロジェクトの以下は可能な限り参考にしたいです。

- フォルダ構成
- コンポーネント分割方針
- 命名ルール、方針
- モジュール構成
- 状態管理方針
- API 呼び出し構成
- 共通部品の考え方

ただし完全一致は不要です。

既存構成よりも新しいバージョンや現在のベストプラクティスが存在する場合は、それらを優先してください。

---

## 制約事項

### 案件ソースの流用禁止

`takazono.olive` は実案件のソースコードです。

そのため、新たに作成する教材プロジェクトでは、独自性があると思われる部分（以下内容など）をそのまま流用しないでください。

- 業務仕様
- 業務ロジック
- テーブル設計
- API 設計
- 項目名
- 業務用語
- マスタ名称

教材用として独自の題材・仕様に置き換えてください。


### バックエンド

バックエンドも AI コーディングで実装しますが、教材の学習対象はあくまでフロントエンドです。

条件は以下をイメージしています。

- DB は SQL Server を利用
- プロジェクト内で完結する構成とする
- `takazono.core` のようなサブモジュール構成は不要
- API は教材用としてシンプルな構成でよい

# 補足

特に重視したいポイントは以下です。

- React 初学者が無理なく学習できること
- 実案件に近い設計・開発体験を得られること

- AI コーディングとの相性が良いこと
