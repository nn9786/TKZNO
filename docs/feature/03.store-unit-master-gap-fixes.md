# 03. Store/Unit Master Gap Fixes vs. Takazono.Olive

## Goal
- Close a set of concrete gaps found when comparing the completed Store/Unit master implementation against the reference project (`Takazono.Olive`'s Ward/Unit masters), scoped to per-master behavior only (not the already-decided architecture simplifications).

## Scope
- Frontend + backend for the two existing masters (`Store`, `Unit`) only.
- No changes to other, not-yet-implemented masters.

## Non-Scope
- Reworking the shared response envelope, role model, or MediatR-less architecture (already intentional simplifications per `docs/training-material-plan.md`).
- Adding the same delete-protection concept to `Store` (Olive's `Ward` has no equivalent concept either).

## Implemented
1. **Naming fix**: renamed `StoreCreateDialog`/`StoreEditDialog`/`UnitCreateDialog`/`UnitEditDialog` to `...Drawer` to match what they actually render (`<Drawer anchor="right">`, not `<Dialog>`).
2. **CSV export i18n**: `DownloadCsv` now accepts a `language` query parameter; backend emits Japanese headers/Shift-JIS or English headers/UTF-8 accordingly (`StoreCsvRowEn`/`UnitCsvRowEn`). Frontend passes the current UI language automatically.
3. **Delete-protection concept** (`UnDeleteFlag`) added to `Unit` only, mirroring Olive's `UnitMedicine.UndeleteFlag`/`CanChangeUseFlag`/`CanUndelete`: a seeded base unit ("個"/EA) can no longer be deactivated or deleted. Enforced server-side (`BusinessRuleAppException`) and reflected in the UI (delete button hidden, use-status switch disabled, "削除不可" chip in list/edit).
4. **Audit info display**: Store/Unit edit drawers now show read-only `Sid` / 登録日時 / 更新日時 / 更新者, sourced from `BaseEntity` fields that already existed but weren't exposed via the DTOs.
5. **Concurrency-conflict UX**: optimistic-concurrency failures now throw a distinct `ConcurrencyConflictAppException` (409, `errorCode: "CONCURRENCY_CONFLICT"`) instead of being indistinguishable from a duplicate-code conflict. The frontend shows a dedicated `ConcurrencyConflictDialog` (forces acknowledgement + reload) instead of a generic error toast.
